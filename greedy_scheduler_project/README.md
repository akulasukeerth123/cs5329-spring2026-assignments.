# Multi-Constraint Greedy Resource Scheduling

## Project Overview

This project implements a multi-constraint scheduling system for tasks running on heterogeneous processors. Each task has a start time, end time, weight, resource requirement, and category. The goal is to choose a subset of tasks that maximizes total weight while satisfying all scheduling constraints.

The project includes:

* two greedy scheduling strategies
* one brute-force baseline for small inputs
* test-case generation for four required scenarios
* benchmark output files for comparing solution quality and runtime

## Files Included

* `scheduler.py`
  Main program. It contains:

  * Greedy Strategy 1: earliest finish time with resource-aware filtering
  * Greedy Strategy 2: weight-to-resource ratio with compatibility checking
  * Brute-force solver for small inputs (`n <= 15`)

* `test_generator.py`
  Generates required test cases and benchmark files.

* `test_cases/`
  Contains input JSON files used for validation and benchmarking.

* `results/`
  Contains output JSON files generated by the program.

* `analysis.md`
  Contains the written justification for both greedy strategies, the brute-force validation discussion, benchmarking analysis, and final reflection.

* `README.md`
  Explains how to run the project.

## Problem Summary

Each task is defined by:

* `start`: earliest start time
* `end`: finish time
* `weight`: priority value
* `resource`: resource units required
* `category`: task type such as compute, io, or network

The scheduler must select tasks so that:

* total overlapping resource usage never exceeds the resource capacity
* no more than `K` tasks from the same category overlap at the same time
* tasks are fully selected or not selected at all

## How to Run the Project

### Step 1: Open the project folder

Move into the project directory:

```bash
cd greedy_scheduler_project
```

### Step 2: Generate test cases and benchmark files

Run:

```bash
python3 test_generator.py
```

This will create:

* required scenario test files
* benchmark input files
* result files for comparison

### Step 3: Run Greedy Strategy 1

```bash
python3 scheduler.py --input test_cases/case1_sparse.json --strategy earliest_finish_resource_aware --output results/case1_g1.json
```

### Step 4: Run Greedy Strategy 2

```bash
python3 scheduler.py --input test_cases/case1_sparse.json --strategy weight_to_resource_ratio --output results/case1_g2.json
```

### Step 5: Run the Brute-Force Baseline

```bash
python3 scheduler.py --input test_cases/case1_sparse.json --strategy bruteforce --output results/case1_bf.json
```

## Edge Cases Handled

The code handles the following edge cases:

* empty task list
* single task
* all tasks overlapping
* tasks with identical parameters
* resource capacity of 1

## Notes

* The brute-force solver is limited to `n <= 15`
* The greedy strategies are much faster and can handle larger inputs
* The brute-force solver is used as the optimal baseline for small test cases
* Output is printed to the terminal and also saved to a JSON file

## Summary

This project shows how greedy scheduling can be applied to a realistic multi-constraint problem. It also shows the limitations of greedy decision-making by comparing the greedy strategies against a brute-force optimal baseline on small inputs.
